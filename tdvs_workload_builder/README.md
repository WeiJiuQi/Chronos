# Chronos TDVS workload builder

`tdvs_workload_builder/` builds reproducible inputs for TANGO and
transformed-vector MIPS systems. The workflow deliberately has four simple
stages:

```text
source vectors
    -> canonical unit-vector base/query
    -> topic-independent or topic-correlated timestamps
    -> exact TDVS ground truth
    -> on-demand MIPS transform
```

The tools are:

| Tool | Purpose |
| --- | --- |
| `prepare_vector_subset` | Convert/split source vectors into one canonical semantic dataset. |
| `generate_time_metadata` | Generate the two defined timestamp workloads. |
| `generate_tdvs_groundtruth` | Compute exact multiplicative or additive TDVS top-k; optionally export MIPS inputs. |
| `export_mips_transforms` | Export one MIPS configuration without recomputing ground truth. |
| `verify_dataset_alignment` | Validate canonical vectors, source IDs, timestamps, transforms, and GT structure. |

## Canonical dataset contract

Source inputs may be:

- `raw`: headerless row-major `float32`;
- `fvecs`: one `int32` dimension before every float32 row; or
- `fbin`: standard global `uint32[N, dim]` header followed by float32 rows.

Canonical outputs are always headerless and row-major:

| File | Type and shape |
| --- | --- |
| `base.fbin` | `float32[N, dim]` |
| `query.fbin` | `float32[Q, dim]` |
| `base_source_row_ids.u64bin` | `uint64[N]` |
| `query_source_row_ids.u64bin` | `uint64[Q]` |
| `manifest_dataset.json` | canonical split, format, normalization, and audit metadata |

For cosine/Chronos workloads, `prepare_vector_subset` writes L2-normalized
vectors by default. It rejects non-finite coordinates and zero-norm rows,
reports exact duplicates, and checks for byte-identical query rows in the
canonical base. When base and query are selected from one source, their source
row IDs are strictly disjoint. Independent real-query files are supported and
may be sampled without changing their source row identity. Use
`--query_sample_mode` when a benchmark needs a prefix base and a deterministic
random subset of its separate query file; otherwise it inherits
`--sample_mode`.

Legacy `*_original_indices.txt` maps and `manifest_ip.txt` are retained for old
scripts. New experiments should use the fixed-width binary row maps and JSON
manifest.

Example with a real headered-fbin query source:

```bash
./build/tdvs_workload_builder/prepare_vector_subset \
  --base /data/source/base.fbin --base_format fbin --base_dim 96 \
  --query /data/source/query.public.10K.fbin --query_format fbin \
  --sample_base 10000000 --sample_query 1000 \
  --sample_mode prefix --query_sample_mode random --seed 42 \
  --metric cosine --normalize_output 1 \
  --compute_control_gt 0 --threads 64 \
  --dataset_name yandex_deep_10m \
  --out_dir /data/chronos/yandex_deep_10m/canonical
```

`--topk K` optionally computes ordinary semantic control ground truth. It is
not TDVS ground truth and is unnecessary for the main experiments.

## Timestamp workloads

Chronos uses two intentionally different workloads. They do not reuse the same
timestamp multiset.

### Topic-independent

Each row receives a creation timestamp independently of its semantic topic:

```text
timestamp_i ~ Uniform(0, H).
```

This models data whose publication time is unrelated to semantic content.

### Topic-correlated

The generator first groups canonical unit vectors with spherical k-means. Each
semantic cluster receives an activity time, then every row is sampled near its
cluster's activity time:

```text
cluster_time_c ~ Uniform(0, H)
timestamp_i ~ TruncatedNormal(cluster_time_cluster(i), sigma^2, [0, H]).
```

The publication defaults are fixed workload parameters rather than index
tuning parameters:

| Parameter | Default |
| --- | ---: |
| horizon `H` | 365 days |
| clusters | `min(N, 256)` |
| training rows | `min(N, 256000)` |
| initialization | k-means++ |
| Lloyd iterations | 15 |
| within-cluster `sigma` | `H/12` (about 30.4 days for `H=365`) |
| seed | 42 |
| threads | 64 |

Training uses a deterministic uniform sample; the final assignment covers every
base row. A truncated normal is sampled directly rather than generated by
clamping, so the model does not create artificial point masses at day 0 or day
`H`.

```bash
./build/tdvs_workload_builder/generate_time_metadata \
  --base_subset /data/chronos/openai1536/canonical/base.fbin \
  --dim 1536 --dataset_name openai1536_1m \
  --out_root /data/chronos/openai1536/meta \
  --distribution all --max_timestamp_days 365 \
  --num_clusters 256 --training_sample_rows 256000 \
  --kmeans_iters 15 --cluster_timestamp_std_days 30.4166667 \
  --seed 42 --threads 64
```

This writes `topic-independent/` and `topic-correlated/` directories. The latter
also contains aligned `cluster_ids.i32bin` and cluster time centers. Each JSON
manifest records timestamp quantiles, exact boundary counts, cluster sizes, and
mean within-cluster timestamp standard deviation.

Timestamps are creation times in `[0,H]`; larger values are newer. They are
never ages and are never part of semantic normalization.

## Exact TDVS ground truth

For unit vectors, timestamp `t_i`, query time `tau=H`, and
`lambda=ln(2)/half_life`:

```text
multiplicative = dot(q, x_i) * exp(-lambda * (tau - t_i))
additive       = alpha * dot(q, x_i)
                 + (1 - alpha) * exp(-lambda * (tau - t_i)).
```

GT is headerless `int64[Q,K]`. Results are ordered by score descending and then
row ID ascending, which makes exact ties deterministic across thread counts.
`--distribution` is required so an artifact cannot silently receive the wrong
workload provenance.

`--tdvs_mode`, `--half_life_days`, and `--metric` are also required: score
semantics and half-life must never depend on implicit experiment defaults.

```bash
./build/tdvs_workload_builder/generate_tdvs_groundtruth \
  --base /data/chronos/openai1536/canonical/base.fbin \
  --query /data/chronos/openai1536/canonical/query.fbin \
  --timestamps /data/chronos/openai1536/meta/topic-correlated/timestamp_days.f32bin \
  --dim 1536 --dataset_name openai1536_1m \
  --distribution topic-correlated \
  --max_timestamp_days 365 --tdvs_mode multiplicative \
  --half_life_days 30,90,180 --topk 100 \
  --metric cosine --threads 64 --export_weighted 0 \
  --out_dir /data/chronos/openai1536/gt/topic-correlated/multiplicative
```

Generate additive GT by replacing `--tdvs_mode multiplicative` with
`--tdvs_mode additive --alpha 0.7`.

## On-demand MIPS inputs

TANGO indexes canonical `base.fbin` plus timestamps. MIPS baselines index a
matching transformed base. Row order never changes.

Multiplicative export:

```text
y_i = exp(-lambda * (H - t_i)) * x_i.
```

The vector norm stores recency, so transformed rows must never be L2-normalized.
The semantic query file remains the MIPS query.

Additive export:

```text
x'_i = [sqrt(alpha) * x_i, sqrt(1-alpha) * decay_i]
q'   = [sqrt(alpha) * q,   sqrt(1-alpha)].
```

The augmented base and query have dimension `dim+1` and must be searched with
inner product.

```bash
./build/tdvs_workload_builder/export_mips_transforms \
  --tdvs_mode multiplicative \
  --base /data/chronos/openai1536/canonical/base.fbin \
  --timestamps /data/chronos/openai1536/meta/topic-correlated/timestamp_days.f32bin \
  --dim 1536 --half_life_days 90 --max_timestamp_days 365 \
  --distribution topic-correlated --dataset_name openai1536_1m \
  --metric cosine --threads 64 \
  --base_out /scratch/openai1536_h90/base_mips.fbin
```

The default manifest is `BASE_OUT.manifest.json`. Generate one transformed
configuration, let all five baselines reuse it, then remove it together with
its KNNG/indexes after results are archived. Canonical data, timestamps, GT,
source row IDs, and manifests are the durable artifacts.

`export_mips_transforms` requires an explicit `--metric`. Its default score
mode is multiplicative; in that mode it rejects query inputs because the
canonical semantic query is reused unchanged.

## Verification

The verifier checks finite/unit canonical rows, timestamp count/range,
fixed-width source IDs and disjointness, exact MIPS coordinate equivalence,
and GT size/range/within-row uniqueness. It supports both score modes.

Multiplicative example:

```bash
./build/tdvs_workload_builder/verify_dataset_alignment \
  --mode multiplicative \
  --base /data/chronos/openai1536/canonical/base.fbin \
  --query /data/chronos/openai1536/canonical/query.fbin \
  --timestamps /data/chronos/openai1536/meta/topic-correlated/timestamp_days.f32bin \
  --transformed-base /scratch/openai1536_h90/base_mips.fbin \
  --dim 1536 --half-life 90 --query-time 365 --metric cosine \
  --base-source-row-ids /data/chronos/openai1536/canonical/base_source_row_ids.u64bin \
  --query-source-row-ids /data/chronos/openai1536/canonical/query_source_row_ids.u64bin \
  --base-source-rows 1000000 --query-source-rows 1000000 --same-source 1 \
  --gt /data/chronos/openai1536/gt/topic-correlated/multiplicative/gt_chronos_multiplicative_cosine.hl90.k100.bin \
  --gt-queries 1000 --gt-width 100 \
  --dataset-name openai1536_1m --distribution topic-correlated \
  --threads 64 --report /data/chronos/openai1536/audit_h90.json
```

For additive data, use `--mode additive --alpha A`, and supply the canonical
and transformed query files with `--query` and `--transformed-query`.

GT structural validation does not independently prove every ranking. The GT
producer performs exhaustive scoring; independent ranking reproduction may be
run separately for selected queries when stronger evidence is required.

## Build

```bash
cmake -S . -B build \
  -DCMAKE_BUILD_TYPE=Release
cmake --build build --parallel 64 --target \
  prepare_vector_subset generate_time_metadata \
  generate_tdvs_groundtruth export_mips_transforms \
  verify_dataset_alignment
```

Every executable supports `--help`. OpenMP is optional. Without it, exact-GT
query parallelism and k-means assignment use `std::thread` fallbacks; remaining
parallel loops run serially.
